## 生成和边界

`prepare-city-layout.py` 将地图轮廓和 CMAB 遥感屋面融合为 XMC1。已有 `street_frontages.py` 沿路分散填入估算矩形，能补街边空缺，但无法恢复住宅院内的组团。基线的 31,221 条普通建筑中，清单记有 1,154 条沿路估算。洪文的空缺来自 3D 底库本身。吕岭的楼形较完整，跨街播散的估算楼和混杂立面模糊了院落关系。另一处变化发生在 6.5 km 水平距离附近，普通小楼会按 1,080 m 网格隐藏。拉高镜头时仍保留近处的同一批楼。

区域清单从 `scenery.js` 随现有资源并行加载。`residential-blocks.js` 只作用于完全落进住宅地块的轮廓，检查边线，避免横跨吕岭花园的校地凹口。既有可信屋面保留坐标、用途及高度。仅把纯沿路估算住宅移出已复核地块。新增开放轮廓单独加入，若将来底库已有相交轮廓则优先保留底库。颜色和远景保留沿用 `city-layout.js` 现有住宅材质与常驻批次。所有屋面仍经过既有地标及场地预留，再按原流程建网格、登记飞行障碍。

共享接入集中在 `scenery.js` 和 `city-layout.js`。合版时如果同期改了建筑加载或绘制循环，应逐段合并并重跑下面两项检查。原 XMC1、地形、水陆资产、老城三个范围的局部模块、航线及界面均保持基线文件。

## 独立复查

1. 使用 Node 20.19+/22.12+ 和 Vite 的现有锁文件。可在独立预览端口运行以下命令。

   ```sh
   npm ci
   npm run build
   npm run preview -- --port 3000
   node tools/check-residential-blocks.mjs
   uv run tools/check-residential-blocks.py
   ```

2. 从起飞大厅点击「空中观光」，启用「自由移动」，按 M 打开航线图后点击无标签处，或先从 [BRT 洪文](http://127.0.0.1:3000/?tour=brt-hongwen&time=afternoon) 进入。洪文核对洪莲中路和前埔西路交会西北面的整组楼排。吕岭从江头向东，核对吕岭路以北、双浦路两侧；可从 [SM 商圈俯视](http://127.0.0.1:3000/?tour=sm-xiamen-top&time=afternoon) 进入再向东移。对照看院内成排形态、楼间空隙和相邻街巷。
3. 同位复拍坐标以米计，X 向东、Z 向南。洪文相机 `(3695,580,-176)` 看向 `(3695,18,-258)`，垂直视角 54°。吕岭相机 `(965,520,-1885)` 看向 `(965,15,-1905)`，垂直视角 58°。对照截图使用 15:00 晴天和 1003 × 646 绘图缓冲。测试夹具在正常起飞后定位相机。
4. 几何检查验证七个地块的范围和互不重叠，八排新增轮廓与底库、游戏道路缓冲、内陆水体、岸线和代表性留空均无相交，逐项报告地形起伏和道路退距。运行时检查核对两条撤掉数据的来源标志、既有轮廓的坐标及高度，测量相同视锥下的城市楼体批次和三角形数。它还核对 252 个西部普通建筑批次的顶点属性与索引哈希，覆盖与老城工作重叠的西侧城市空间。

## 实施方验收结果

- 两版生产构建成功，Vite 仍提示大型分块。独立云环境的 Chromium 使用 SwiftShader，Playwright 从起飞大厅进入场景并打开航线图。洪文同机位可看到八排长屋面和中间留空。吕岭三组临街院落的区分更清楚。SM 商圈与老城两处固定机位的实际总绘制调用、三角形计数前后相同。全程未记录页面异常、控制台错误或 HTTP 失败。
- 纯建筑层离线同视锥统计如下。城市建筑总批次为 507 → 507。本轮修改范围之外的 252 个西部批次哈希逐个一致。视锥统计排除了云、交通和植被，单位为三角形或提交的建筑批次。

| 机位 | 建筑批次 | 三角形 |
| --- | ---: | ---: |
| 洪文同机位 | 12 → 12 | 69,926 → 70,064 |
| 吕岭同机位 | 8 → 8 | 57,537 → 57,517 |
| 吕岭约 7.1 km 外 | 105 → 105 | 545,749 → 547,598 |

- 洪文新增屋面离游戏道路缓冲至少 30.6 m。缓冲包含道路网格半宽和额外 2 m。单楼地面高差小于 3.5 m，25 m 地形网格插值测得最大局部坡度为 12.4%。另用 2026-11-25 OSM 道路抽查，新屋面距最近道路中心线约 35 m。
