[原可玩版基线](baseline.mp4)依次播放海岸与山坡。两部机位对照短片每侧 800 × 450，左为修复前，右为修复后，共 25 帧。第 1–3 帧完全冻结，第 4–8 帧冻结天气并让镜头往返 0.000065 弧度，第 9–14 帧缓慢转向，第 15–20 帧向前侧平移并升高，第 21–25 帧改变视场角。后 17 帧每帧推进 1/24 秒。787 短片单独调用航线飞行模型按 1/60 秒积分，每 0.1 秒取一帧，16 帧中飞行约 119 米。所有短片以每秒 8 帧播放，供观察细节。

配对采样使用同一次源码快照、相同随机种子 123456 和同一批 71 份公共资源。两边资源清单摘要相同，为 `8f6359da4d59243930ce53d07b5f24c443fead35e72d38672553a744bd0c8112`。采样器暂停浏览器自动推进，调用游戏渲染入口逐帧记录，已核对每对镜头的位置、姿态与视场角一致。[逐帧相机、原始耗时、测区坐标与统计](measurements.json)

## 成因和修复

| 测区 | 单变量复现 | 渲染入口改动 |
| --- | --- | --- |
| 平视远海 | 微转时海面平均色差为 0.142。关闭云层倒影降到 0.054，抹平水面法线降到 0.053。关闭桥岸平面反射和太阳圆盘分别为 0.143、0.142。波面反射方向变化放大了云图欠采样。 | `clouds.js` 对预乘颜色与透明度的云图建立 mip 链，`atmosphere.js` 根据反射方向在一个屏幕像素内覆盖的范围选级，并处理方位角接缝。波浪、太阳反光带和桥岸反射仍参与渲染。 |
| 岸线、贴地路面 | 同镜头仅把近裁面从 0.55 米调至 4 米，岸线色差从 0.415 降至 0.303。源码中部分主路另有整幅路床与沥青仅相隔约 2.6 厘米。 | `free-camera.js`、`view.js`、`game.js` 按室外相机离地及附近障碍的净空调节近裁面。保留座舱、舷窗所需的近距离视野。`scenery-streets.js` 将主路路床收为两条路肩，与沥青共边，保留标线。 |
| 山坡、树冠、路旁地表 | 隐藏树冠使林区色差从 0.389 降至 0.219。固定地表噪声使道路测区从 0.081 降至 0.067。两机位分别关闭阴影，固定天气下的均值基本相同。 | `geography.js` 按每像素覆盖的地面距离衰减过细的程序纹理。`scenery-groves.js` 在多重采样目标上按像素覆盖率画树冠边缘，单采样反射中使用原有剪裁阈值。 |

两个机位的近景地形使用固定网格，外海为一张水面，内陆水体独立生成。此次样本未观察到运动触发的地形层级切换或两张外海水面重叠。道路路床重叠来自几何检查，其单独贡献未量化。[逐项关闭时的测量结果](ablation.csv)

## 画质与耗时

下表为冻结天气、微转镜头的一对原始 PNG 帧。对每个像素计算 RGB 三通道绝对差的平均值，再在测区汇总。数值范围 0–255，包含正常轮廓运动。完全静止时，两版各测区的最大差值均为 0。慢转、平移及缩放阶段还包含真实光流，各段的二阶帧差单列在原始数据中。

| 测区 | 平均变化，前 → 后 | 第 99 百分位，前 → 后 |
| --- | ---: | ---: |
| 海面 | 0.142 → 0.069 | 1.33 → 0.67 |
| 远岸与岸线 | 0.415 → 0.249 | 5.67 → 3.33 |
| 道路及邻近地表 | 0.081 → 0.069 | 0.67 → 0.67 |
| 山坡树冠 | 0.389 → 0.364 | 6.00 → 7.00 |

海面平均 RGB 亮度从 144.62 到 145.04。树冠的平均变化略降，但最明显的少量跳点仍在，差值大于 6 的像素占比从 0.98% 增至 1.18%。

| 机位 | 修复前中位 / P95 | 修复后中位 / P95 |
| --- | ---: | ---: |
| 演武大桥 | 11.8 / 34.2 ms | 4.0 / 16.2 ms |
| 东坪山 | 25.5 / 65.8 ms | 18.8 / 27.8 ms |

设备为 Apple M5，macOS 26.6.2，ego-browser Chromium 156，ANGLE Metal，WebGL 2、24 位深度、DPR 1。耗时指一次游戏渲染加单像素同步回读，前后同尺寸，各取第 4–25 帧。短序列的耗时受 GPU 排队与后台负载影响，不能折算为长期游戏帧率。

## 追加定位　高崎货场、东坪山树冠与纹理单元

**高崎铁路货场。** 演武大桥、东坪山、厦门大桥、高崎 T3、787 海沧湾共用整座城市的初始化。首版正式包 `game-Dr11to1x.js` 在创建场景时就能离线重现告警，无须移动相机。逐网格检查定位到「厦门高崎站 · 国铁货运Ⅰ、Ⅱ场」。240,441 个顶点中有 30,480 个的 X、Z 非有限，影响 15,348 个索引三角形。早先配对基线尚未包含这处铁路资产，1,687 个网格的位置属性均有限。

轨道侧面的生成代码把 `measuredPath.sections()` 输出的截面记录传给了 `offset()`。截面提供横向偏移 `rx/rz`，而 `offset()` 读取沿线切向 `ux/uz`。在首版包的诊断副本里，仅将轨侧边点改为 `[x + rx * side, y, z + rz * side]`，原网格的坏顶点即从 30,480 降为 0，包围球半径由 NaN 恢复为 1,454.27 米。

正式服务 5187 后续提供的 `game-COjByyfW.js` 已包含相应轨侧修正。按服务返回的 HTML 追踪实际加载的 JS，并与磁盘构建逐字节核对，再离线调用包内地形及场景构造函数。1,691 个网格的位置属性全部有限，高崎货场 247,905 个顶点、包围球半径 1,536.84 米。网格数量与大小含同期新增模型。离线检查使用真实测绘与布局资源，省略贴图绘制，海岸距离图使用原图和双线性缩小副本。所属模块为 `src/landmark-gaoqi-railway.js` 的 `tracks()`，其截面接口见 `src/old-town-layout.js` 的 `measuredPath()`。两版完整游戏模块的 SHA-256 收入下方原始数据。

**东坪山树冠。** 原始 PNG 的相同姿态往返对比逐像素一致。冻结天气并微转时，首版林区 P99 从 6 升至 7，但 P99.9 从 36.33 降至 15.67，最大值从 115 降至 32。超过 6 的像素中有 999 个是修复前未越线的像素，另有 782 个回落到阈值以下。使用关闭树冠前后的两步镜头建立树冠像素掩膜，999 个新增越线像素中有 978 个在掩膜内或距它不超过一像素。这支持运动时树冠遮罩的亚像素覆盖率在轮廓附近重新分配。加宽过渡的试验版本使 P99 升至 7.33，常规慢转的均值也从首版的 2.12 升至 2.21。保留首版着色器和已记录的海岸、道路结果。

**纹理单元告警。** M5 的 WebGL 2 上下文报告片元阶段 16 个单元，所有阶段合计有 32 个可绑定单元。32 × 32 单材质算例使用游戏地表、海面、湖面着色器和小测试纹理；在三纹理预绘制之后，首次绘制地表触发环境图预过滤，地表的 15 个活动片元采样器分配到 3–17。Three.js 将顺序分配编号与片元单元数量比较，产生 17、18 两条提示。后续同材质绑定到 0–14，整个画布的 4,096 字节 RGBA 完全一致，两个绘制均返回 `NO_ERROR`。单独绘制海面和湖面分别使用 10 和 6 个活动采样器，均有非空图像。这次设备与绘制路径未观察到可见降级，未改动纹理和渲染器。其他 GPU、驱动或材质变体尚未实测。
